# スマートタスク登録ガイド

Claude Code がタスクを自動分析し、適切に親子構造で登録するための完全ガイド

---

## 概要

**スマートタスク登録**は、Claude Code の AI 能力を活用して、ユーザーから依頼されたタスクを自動的に分析し、必要に応じてサブタスクに分割して登録する機能です。

### 主な機能

1. **タスク複雑度の自動分析**
   - タスクのタイトル、説明、期限などから複雑度を判定
   - 複雑度スコア（0-100）を計算

2. **自動サブタスク提案**
   - 複雑なタスクを適切なサブタスクに分解
   - プロジェクトタイプに応じた適切な分割

3. **期限の自動配分**
   - 親タスクの期限から、サブタスクの期限を均等配分
   - 実行可能なスケジュールを自動生成

---

## Claude Code の使い方

### 基本的な使い方

ユーザーが以下のように依頼した場合、Claude Code は自動的に `smart-task-add` Skill を活用します：

```
例1: "Webアプリ開発のタスクを登録して"
例2: "新規プロジェクトのタスクを追加したい"
例3: "システム移行のタスクを作成して、期限は2ヶ月後"
```

### Claude Code の判断フロー

```
ユーザーの依頼
    ↓
タスク内容を分析
    ↓
複雑度を判定 (スコア計算)
    ↓
┌─────────────────┐
│ スコア < 40     │ → 単一タスクとして登録
│ (シンプル)      │
└─────────────────┘
    ↓
┌─────────────────┐
│ スコア >= 40    │ → サブタスクへの分割を提案
│ (複雑)          │
└─────────────────┘
    ↓
ユーザーに確認
    ↓
親タスク + サブタスクを自動作成
    ↓
期限を自動配分
```

## タスク複雑度の判定基準

### スコアリング要素

| 要素 | 条件 | 加点 | 理由 |
|------|------|------|------|
| **タイトルの長さ** | 30文字以上 | +15 | 複雑な内容を示唆 |
| **複雑キーワード** | 「プロジェクト」「開発」「実装」「システム」など | +20 | 大規模タスクの可能性 |
| **複数ステップ** | 「から」「まで」「および」などが2箇所以上 | +15 | 複数の作業ステップを含む |
| **期限の長さ** | 2週間以上先 | +20 | 長期的なタスク |
| **期限の長さ** | 1週間以上先 | +10 | 中期的なタスク |
| **説明文の長さ** | 100文字以上 | +10 | 詳細な要件がある |

### 判定しきい値

- **スコア 0-39**: シンプルなタスク → 単一タスクとして登録
- **スコア 40-100**: 複雑なタスク → サブタスクへの分割を推奨

## 自動サブタスク提案のパターン

### 1. 開発・実装系タスク

**キーワード**: 「開発」「実装」「システム」「アプリ」「機能」

**推奨サブタスク**:
```
1. [タスク名] - 要件定義
2. [タスク名] - 設計
3. [タスク名] - 実装
4. [タスク名] - テスト
5. [タスク名] - レビュー・修正
```

**例**:
```
親タスク: Webアプリケーション開発
期限: 2026-03-15 (60日後)

→ 自動分割:
  1. Webアプリケーション開発 - 要件定義 (期限: 2026-01-27)
  2. Webアプリケーション開発 - 設計 (期限: 2026-02-08)
  3. Webアプリケーション開発 - 実装 (期限: 2026-02-20)
  4. Webアプリケーション開発 - テスト (期限: 2026-03-04)
  5. Webアプリケーション開発 - レビュー・修正 (期限: 2026-03-15)
```

### 2. プロジェクト系タスク

**キーワード**: 「プロジェクト」「企画」

**推奨サブタスク**:
```
1. [タスク名] - 計画立案
2. [タスク名] - リソース確保
3. [タスク名] - 実行
4. [タスク名] - 進捗確認
5. [タスク名] - 完了報告
```

### 3. 調査・研究系タスク

**キーワード**: 「調査」「研究」「リサーチ」

**推奨サブタスク**:
```
1. [タスク名] - 情報収集
2. [タスク名] - 分析
3. [タスク名] - レポート作成
```

### 4. 移行・アップグレード系タスク

**キーワード**: 「移行」「アップグレード」「リファクタリング」

**推奨サブタスク**:
```
1. [タスク名] - 現状調査
2. [タスク名] - 移行計画
3. [タスク名] - テスト環境での検証
4. [タスク名] - 本番環境への適用
5. [タスク名] - 動作確認
```

### 5. 一般的なタスク

**上記に該当しない場合**

**推奨サブタスク**:
```
1. [タスク名] - 準備
2. [タスク名] - 実行
3. [タスク名] - 確認・完了
```

## 期限の自動配分ロジック

### 基本方式: 均等配分

親タスクの期限を、サブタスク数で均等に分割します。

**計算式**:
```
総日数 = (親タスク期限 - 今日)
サブタスクあたりの日数 = 総日数 / サブタスク数

各サブタスクの期限:
  サブタスク1: 今日 + (サブタスクあたりの日数 × 1)
  サブタスク2: 今日 + (サブタスクあたりの日数 × 2)
  ...
  最後のサブタスク: 親タスクの期限と同じ
```

### 例

**親タスク**: 「システム移行」
- 期限: 2026-02-15 (30日後)
- サブタスク数: 5

**自動配分結果**:
```
総日数: 30日
サブタスクあたりの日数: 30 / 5 = 6日

1. 現状調査 → 期限: 2026-01-22 (6日後)
2. 移行計画 → 期限: 2026-01-28 (12日後)
3. テスト環境での検証 → 期限: 2026-02-03 (18日後)
4. 本番環境への適用 → 期限: 2026-02-09 (24日後)
5. 動作確認 → 期限: 2026-02-15 (30日後、親タスクと同じ)
```

### 期限がない場合

親タスクに期限が設定されていない場合、サブタスクにも期限は設定されません。
ユーザーが後から個別に設定できます。

**ユーザー**: "新規ECサイト開発のタスクを登録して。期限は2ヶ月後で、優先度は高で"

**Claude Code の判断**:
```
タイトル: "新規ECサイト開発"
期限: 2026-03-16 (60日後)
複雑度スコア:
  - 複雑キーワード「開発」: +20
  - 期限2週間以上: +20
  - タイトル15文字以上: +15
  合計: 55点

→ サブタスクへの分割を提案
```

**実行コマンド**:
```bash
python3 scripts/smart_task_add.py \
  --title "新規ECサイト開発" \
  --priority high \
  --due 2026-03-16 \
  --yes
```

```
親タスク: 新規ECサイト開発 (ID: 42, 期限: 2026-03-16)
├─ 新規ECサイト開発 - 要件定義 (ID: 43, 期限: 2026-01-28)
├─ 新規ECサイト開発 - 設計 (ID: 44, 期限: 2026-02-09)
├─ 新規ECサイト開発 - 実装 (ID: 45, 期限: 2026-02-21)
├─ 新規ECサイト開発 - テスト (ID: 46, 期限: 2026-03-05)
└─ 新規ECサイト開発 - レビュー・修正 (ID: 47, 期限: 2026-03-16)
```

## 使用上の注意点

### 1. 複雑度判定の限界

現在の実装は**ルールベース**の判定です。以下の点に注意してください：

- **キーワードマッチング**: 特定のキーワードに依存するため、文脈を完全に理解するわけではありません
- **誤判定の可能性**: シンプルなタスクでも複雑と判定される場合や、その逆もあります
- **ユーザーの確認が重要**: 自動提案はあくまで提案であり、最終判断はユーザーが行います

### 2. カスタマイズの推奨

プロジェクトやチームの特性に応じて、以下をカスタマイズすることを推奨します：

- **キーワードリスト**: `scripts/smart_task_add.py` の `complex_keywords` を編集
- **スコアリング**: 各要素の加点を調整
- **しきい値**: 分割推奨スコア（デフォルト: 40）を変更
- **サブタスクパターン**: プロジェクトタイプごとの推奨サブタスクを追加・変更

### 3. 手動調整も可能

自動登録後も、通常のCLIコマンドで調整できます：

```bash
# サブタスクを追加
ai-task-manager add "追加タスク" --parent 42

# 期限を変更
ai-task-manager update 43 --due 2026-02-01

# タスクを削除
ai-task-manager delete 44
```

## トラブルシューティング

### Q1. 自動分割されない

**原因**: 複雑度スコアが40未満

**対処法**:
1. `--subtasks` オプションで手動指定
2. スクリプトのスコアリングロジックを調整

### Q2. 不適切なサブタスクが提案される

**原因**: キーワードマッチングの限界

**対処法**:
1. インタラクティブモードで `edit` を選択し、手動でサブタスクを編集
2. `--subtasks` オプションで明示的に指定

### Q3. 期限配分が不適切

**原因**: 均等配分がプロジェクトに合わない

**対処法**:
1. 登録後、`ai-task-manager update` で個別に調整
2. スクリプトの `calculate_subtask_deadlines` 関数をカスタマイズ（重み付け配分など）

## 応用例

### 例1: 大規模プロジェクトの構造化

```bash
# 親タスク: プロジェクトA
python3 scripts/smart_task_add.py \
  --title "プロジェクトA" \
  --category Work \
  --priority high \
  --due 2026-06-30

# → 5つのサブタスクに自動分割

# さらに、各サブタスクを詳細化
ai-task-manager add "要件ヒアリング" --parent 43
ai-task-manager add "要件仕様書作成" --parent 43
ai-task-manager add "UI設計" --parent 44
ai-task-manager add "DB設計" --parent 44
```

### 例2: チームでの標準化

チーム全体で同じパターンを使うことで、タスク管理を標準化できます：

```bash
# 開発タスクは常に5段階に分割
python3 scripts/smart_task_add.py \
  --title "機能X開発" \
  --subtasks "要件定義" "設計" "実装" "テスト" "レビュー" \
  --yes
```

## まとめ

**スマートタスク登録**により、Claude Code は：

✅ タスクの複雑さを自動判断
✅ 適切なサブタスクに自動分割
✅ 期限を実行可能なスケジュールに自動配分
✅ ユーザーの手間を大幅に削減

これにより、大規模なプロジェクトやタスクも、構造化された管理が簡単に実現できます。
